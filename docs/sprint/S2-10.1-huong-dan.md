# S2-10.1 — Tải ảnh bìa hợp lệ cho đầu sách

Bộ patch dành cho source DuAnTTCS_N5(20261003-075131).zip. Không dùng đè lên một bản source khác đã được nhóm sửa thêm mà chưa đối chiếu.

## 1. Phạm vi và cách triển khai

- Thủ thư, Quản lý thư viện và Admin tải ảnh theo quyền biên mục đang có. Bạn đọc không có quyền tải ảnh; backend kiểm tra quyền thật.
- Menu Đầu sách → dưới tên sách chọn **Chỉnh sửa ảnh bìa**. Hoặc mở chi tiết đầu sách → Chỉnh sửa ảnh bìa. Màn hình sửa chỉ phục vụ ảnh bìa trong lát này, không thêm chức năng sửa thông tin thư mục.
- Chấp nhận JPG (.jpg, .jpeg) hoặc PNG; backend xác minh nội dung thực tế và giải mã ảnh, không tin riêng đuôi/MIME. Tệp rỗng, giả mạo, sai định dạng, quá dung lượng bị từ chối.
- 3MB được thống nhất là 3 × 1024 × 1024 = **3.145.728 byte**. Đúng mốc được nhận; lớn hơn 1 byte bị từ chối.
- Giữ nguyên ảnh đang có khi upload lỗi. Đã có ảnh thì không được upload lần hai, kể cả gọi API trực tiếp. Hai upload đồng thời khóa cùng đầu sách, chỉ một lần lưu được.
- Sau khi lưu, chuyển về chi tiết đầu sách, hiện thông báo thành công và ảnh đã lưu. Refresh trang vẫn đọc ảnh từ backend.
- Giữ trường books.cover_image_url đã có ở V17; tạo V19 chứa ảnh gốc trong bảng book_cover_images (BYTEA). Không sửa migration cũ. Ảnh và URL lưu chung transaction để rollback khi lỗi.
- Tách entity/repository ảnh để truy vấn danh sách sách không tải theo toàn bộ byte ảnh. BookCoverService/BookCoverController chỉ xử lý multipart và phản hồi ảnh nhị phân, không tạo thêm bộ CRUD/biên mục song song. Các API JSON ở BookCatalogController được giữ nguyên.
- Không thêm dependency, biến môi trường, thư mục upload hoặc dịch vụ ngoài. Cập nhật application.yml để servlet nhận file 3MB và request 4MB (chừa phần header multipart).
- Tái sử dụng layout, Button/Card/PageHeader, apiClient có JWT và refresh token, ErrorResponse/ApiException và cơ chế tự đăng ký feature.tsx.

**Ngoài phạm vi:** ảnh mặc định mới, thumbnail danh sách, thay thế/xóa ảnh cũ, sửa thông tin thư mục. Trang tra cứu vốn đã có phần dự phòng khi thiếu ảnh; patch giữ nguyên phần đó, không bổ sung ảnh mặc định.

## 7. Gọi API để test phân quyền và giữ ảnh cũ

Ẩn nút chưa chứng minh được phân quyền; các test này cần gọi API trực tiếp.

Trên trình duyệt đã đăng nhập, mở F12 → Console, nhập `localStorage.getItem('libra_access_token')`, copy giá trị token (không kèm dấu nháy ngoài). Dùng token riêng của tài khoản đang test; không chia sẻ token.

Mở PowerShell. Thay ID và đường dẫn bằng đầu sách/file thật:

```powershell
$bookId = 7
$token = Read-Host 'Dan access token cua tai khoan dang test'
$filePath = 'C:\duong-dan\TEST_DATA_S2-10.1\06-fake.jpg'
curl.exe -i -X POST "http://localhost:8080/api/v1/books/$bookId/cover" -H "Authorization: Bearer $token" -F "file=@$filePath"
```

- Token Thủ thư + fake JPG/GIF: 400 INVALID_BOOK_COVER; file vượt 3MB bị servlet chặn: 413 INVALID_BOOK_COVER. Cả hai có thông báo JPG/PNG, tối đa 3MB.
- Token Thủ thư + file hợp lệ + sách đã có ảnh: 409 BOOK_COVER_ALREADY_EXISTS.
- Token Bạn đọc + file hợp lệ nhỏ: 403. Dùng file nhỏ để test quyền, tránh lỗi giới hạn multipart che lỗi quyền.
- Không token: dùng lệnh tương tự nhưng bỏ `-H "Authorization: Bearer $token"` → 401.
- Không tồn tại ID: dùng file hợp lệ → 404 BOOK_NOT_FOUND.
- Upload thành công: 204 No Content; frontend tự chuyển sang chi tiết để đọc ảnh.
- GET `/api/v1/books/{id}/cover`: ảnh dành cho các vai trò quản lý, có JWT, dùng được khi sách chưa có bản sao.
- GET `/api/v1/books/public/{id}/cover`: ảnh công khai khi sách đã có bản sao; trả 404 nếu chưa công khai hoặc chưa có ảnh.

## 8. Test tự động và kết quả thực tế

**Đã thực hiện trong môi trường triển khai patch:**

- Compile backend Java 17 cùng code test thành công.
- 25 test mới: 19 lượt BookCoverServiceTest và 6 BookCoverControllerTest đều pass.
- Tổng nhóm test ảnh bìa + hồi quy: **94 tests, 0 failures, 0 errors, 0 skipped**.
- Hồi quy gồm biên mục, chi tiết công khai, controller tra cứu/lọc/phân trang, tổng bản sao, phân quyền và khóa tài khoản đăng nhập.
- `npm run build`: TypeScript + Vite thành công. Vite có cảnh báo chunk lớn hơn 500kB; không phải lỗi build.

**Chưa thực hiện:** migration V19/JPA/transaction/khóa đồng thời trên PostgreSQL thật; thử upload bằng HTTP tới servlet đang chạy; kiểm thử/quan sát giao diện trong trình duyệt (Chromium không tải được trong môi trường này). Test controller dùng MockMvc và service mock, không chứng minh được multipart parser của servlet thật. Test service dùng repository mock, không thay thế test database. Cần chạy checklist mục 6 trên máy bạn trước khi merge.

## 9. Demo cho giảng viên (1–3 phút)

1. Đăng nhập Thủ thư, vào Đầu sách, chọn đầu sách chưa có ảnh → Chỉnh sửa ảnh bìa.
2. Giới thiệu màn hình có tên/mã/ISBN, chỉ nhận JPG/PNG tối đa 3MB.
3. Chọn GIF rồi file lớn hơn 3MB: chỉ ra thông báo từ chối rõ giới hạn.
4. Chọn ảnh JPG/PNG hợp lệ → Lưu ảnh bìa.
5. Chỉ ra thông báo thành công, ảnh trên chi tiết đúng đầu sách; F5 chứng minh đã lưu.
6. Mở lại màn hình ảnh: đã có ảnh nên chưa hỗ trợ thay thế trong S2-10.1. Không demo thumbnail/ảnh mặc định vì thuộc lát sau.
